# Portfolio design direction

Proposed plan; visual redesign is not implemented yet.

## 1. Establish a consistent visual direction

Use an editorial studio style: charcoal background (#0B0D12), warm white text (#F3F0E9), muted silver secondary text (#A5ACB8), and one icy-blue accent (#A9C7FF). Reserve warm amber for the desk lamp. Check text contrast against the final composited glass backgrounds. Use glass for navigation and selected cards rather than every surface.

Create desktop and mobile mockups before changing the whole site. Keep the silver laptop, simplify competing blue/purple glows, and use generous spacing and a consistent type scale.

## 2. Make the opening and hero feel intentional

Retain the desk-to-screen transition, but make the mobile desk framing larger and shorten the mobile scroll journey if device testing supports it. Keep mouse, notebook and mug hover animation exclusive to a desktop-sized viewport with a fine pointer and hover support. Touch scrolling must never depend on hover.

Hero copy proposal: “Akashjeet Dutta” / “Building thoughtful software. Learning in public.” Add two clear links: Explore my work and GitHub (once its destination is confirmed). Avoid invented titles, experience or project metrics.

## 3. Give the work real substance

Preserve the agreed order: desk → hero → certificates → projects → toolkit. Make BlindSpot the featured project with actual screenshots, the problem, the approach, technologies, current status and verified repository/demo links. Give the CS50P project a real name, description and image. Upload the actual certificate and its verification link; remove pending copy only when those assets exist.

Use one strong featured project layout with quieter supporting cards. Avoid filling every section with identical glass boxes.

## 4. Finish the personal details

Add a concise about section, verified contact/social links and a simple footer. Remove the “LOCAL PROTOTYPE” label during the visual release. Organize projects and certificates as structured data so additions do not require layout edits. Keep claims about proficiency and accomplishments factual.

## 5. Validate before publishing the redesign

Check narrow and wide phone layouts and desktop layouts; test actual mobile Safari/Chrome when devices are available. Verify text contrast, readable type, keyboard focus, reduced motion, touch navigation, rapid 3D toggles, loading/fallback states and layout stability. Measure scrolling at the new Retina resolution on physical hardware before claiming 60 fps. Keep a clear fallback for weaker devices rather than silently making all phones blurry.

## Suggested sequence

First create one hero/desk colour study at phone and desktop widths. Then implement the approved visual system, add real project/certificate content, and finish with interaction and device checks. No framework migration or paid assets are needed for this plan.
